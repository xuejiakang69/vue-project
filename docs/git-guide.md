# Git 提交规范

> Commit Message 格式和分支策略。

---

## 一、Commit Message 格式

采用混合规范：

```
<type>(<scope>): <subject>
```

### Type 类型

| type | 说明 | 示例 |
|------|------|------|
| `feat` | 新功能 | `feat(用户模块): 新增登录页面` |
| `fix` | 修复 bug | `fix(购物车): 修复数量计算错误` |
| `docs` | 文档更新 | `docs(api): 更新接口文档` |
| `style` | 样式调整 | `style(首页): 调整布局样式` |
| `refactor` | 重构 | `refactor(订单): 重构状态管理` |
| `perf` | 性能优化 | `perf(商品列表): 优化渲染性能` |
| `test` | 测试 | `test(登录): 添加单元测试` |
| `chore` | 构建/工具 | `chore: 更新依赖版本` |

### Scope 范围

可选，表示影响的模块：

- `用户模块`、`商品模块`、`订单模块` 等业务模块
- `路由`、`Store`、`样式` 等技术模块
- 省略时表示全局改动

### Subject 主题

- 简短描述，不超过 50 字
- 使用中文
- 不以句号结尾

## 二、分支策略

### 分支说明

| 分支 | 用途 | 部署环境 |
|------|------|----------|
| `main` | 生产分支 | 生产环境 |
| `test` | 测试/开发分支 | 测试环境 |

### 开发流程

```
1. 在 test 分支开发功能
2. 测试通过后合并到 main
3. push 到 main 自动部署生产环境
4. push 到 test 自动部署测试环境
```

---

## 三、提交规则

- **Claude 不主动提交代码**
- **只在用户明确要求时才执行 git commit**
- 用户要求提交时，按上述格式组织 commit message
